⚠️ OpenTelemetry Collector v0.157.0 modifies histogram metric boundaries.

This week, OpenTelemetry Collector v0.157.0 introduced changes to the histogram bucket definitions for certain metrics, requiring users to adjust dashboards or alerts that rely on the previous metric structures. Several projects, including Crossplane, Flux2, and SeeBOM, released patch updates addressing specific bugs and security concerns.

🚀 Key releases

OpenTelemetry Collector v0.157.0: This release modifies the histogram bucket boundaries for `otelcol_exporter_queue_batch_send_size_bytes` and `otelcol_processor_batch_send_size_bytes` metrics. This change means that monitoring systems and dashboards configured with previous definitions for these metrics may require updates to accurately reflect new data.

Crossplane v2.3.4, v2.2.4, v2.1.8, v1.20.11: Multiple patch releases across different Crossplane versions fixed an issue where the Usage controller repeatedly updated owner references for composed Usages. This correction addresses unnecessary API calls and potential reconciliation loops within the control plane.

Flux2 v2.9.3: This patch release resolves several issues. It fixes empty lines vanishing from rendered Helm chart manifests, corrects a behavior where HelmReleases were marked as tested even when their Helm test hooks did not execute, and addresses a bug where `spec.images` entries would discard previously declared image fields if only a subset of fields were set.

SeeBOM v0.6.0 (now BOMHort): This version includes a rebrand of the project to BOMHort. It adds a faceted global search capability, resolves issues with Kubernetes health probes, and incorporates a comprehensive security patch sweep for its Go components, UI, and dependencies.
