🚀 Kuma 3.0 Released, Requires Upgrade Path Adjustments

Kuma 3.0, a major release for the service mesh, was published this week. This version removes previously deprecated legacy APIs and modifies several default behaviors, necessitating an upgrade guide review before deployment.

🚀 Key releases

Kuma v3.0.0: This major release removes legacy APIs that were deprecated in earlier 2.x versions and alters several default configurations. Upgrades require consulting the provided guide to adapt deployments.

Strimzi-kafka-operator 1.3.0: This release now supports only Kubernetes 1.32 and newer, ending support for Kubernetes 1.30 and 1.31. It also enforces the `v1` CRD API, removing support for older `v1beta2`, `v1beta1`, and `v1alpha1` APIs.

Envoy v1.40.0: The build system for Envoy has transitioned from using `WORKSPACE` to `bzlmod`. This is a breaking change, requiring downstream projects to migrate to `MODULE.bazel`.

containerd v2.4.2, v2.3.7, v2.2.10, v2.0.14: Patch releases were issued across multiple stable versions to address security vulnerabilities. These include CVE-2026-95839 and GHSA-hc94-p972-ch66.

Volcano v1.16.0: This version introduces NamespaceQueue and the fairshare plugin. These additions enable tenants to manage queue hierarchies and quotas within their own namespaces, utilizing administrator-authorized resource pools.
