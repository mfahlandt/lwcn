## 👋 Welcome
This week in Cloud Native saw numerous project updates focusing on security, performance, and AI workload orchestration. The community also introduced new open-source tools for AI agent development, Git operations, and Kubernetes API management.

## 📰 This Week in Cloud Native

The Cloud Native ecosystem saw a focus on security enhancements and continued advancements in AI workload management this week. OpenSSF announced the release of **Zarf 1.0**, which introduces the v1beta1 schema, stronger package signing, and improved stability for air-gapped software delivery environments. The OpenSSF also published an article on the "AI Security Gap" in routine maintenance, noting that the rapid introduction of external dependencies by AI coding tools can outpace review capabilities. In response to recent vulnerabilities, **Podman v6.2.0** and **v5.8.10** were released, addressing CVEs related to untrusted image labels in auto-update and potential bypasses of Digest and Signature validation. **Open Policy Agent (OPA) v1.22.4** and **kgateway v2.5.2** included fixes for CVE-2026-97054, a vulnerability in Go's HTTP/1 server. **Kyverno v1.20.0** addressed CVE-2026-50163 in its `oras-go` dependency, and **OpenShell v0.1.8** modified its default credential resolution behavior for security.

In AI and workflow orchestration, the open-source project **Hive** released numerous updates. These enhancements focused on agent interaction and knowledge management, including agent output markers generating `output-signal` kick events and a new system for ID-addressed queued kicks with status tracking. Usage visibility for AI providers was improved, and extensive knowledge integrations were added for platforms such as Otter.ai, Granola, Fathom, Slack huddles, Discord, Zoom, and Microsoft Teams, alongside Deepgram transcription capabilities. Security for interactive agent sessions was strengthened by running them with unprivileged UIDs in private sandboxes, and secrets at rest are now encrypted using an OpenBao Transit keystore provider. The platform also introduced automated derivation of reference repositories from accepted issues and optional GitHub API budget pacing to prevent rate limit exhaustion. **KAI-Scheduler v0.19.0** added support for GPU memory and fraction limits and refined Memory Manager NUMA group modeling for scheduling.

The broader container and Kubernetes ecosystem also saw notable updates. **Harbor v2.16.0** replaced Redis with Valkey as its cache backend and introduced full multi-architecture enablement. **Kube-OVN v1.17.1** improved IPsec cleanup and pod policy reconciliation, with a default behavior change to no longer skip conntrack for direct logical-port traffic. **Kuberhealthy v3.1.0** expanded its native monitoring capabilities by adding built-in HTTP and TCP health checks that run directly from the controller. New open-source projects garnered community attention, including **Litek8s**, a Kubernetes API implemented in a single Rust binary, and **DuckLake 1.1**, aimed at simplifying data lake complexity. Other emerging projects discussed included **Langfuse AI Gateway** for tracing LLM calls, **QueenMQ** as a new message broker, **Bot-bottle** for secure agent runtime, **Althar** as an IDE with agent review capabilities, and **Rbit** for self-hosted Git forge functionality.
